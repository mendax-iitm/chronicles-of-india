# Handover to Claude Code

Three steps. Total time to first working session: about five minutes.

---

## Step 1 — Put the repo on disk

```bash
cd ~/Side\ Projects
unzip ~/Downloads/chronicles-of-india.zip
cd chronicles-of-india
git log --oneline          # should show 2 commits already
open index.html            # sanity check: drag the slider, it should work
```

The repo already has git initialised with two commits. Do not `git init` again.

## Step 2 — Create the public repo

```bash
gh repo create chronicles-of-india \
  --public \
  --source=. \
  --remote=origin \
  --description "Interactive historical atlas of India, 600 BCE to 1947 CE — timeline map, rulers, place genealogy, journeys and a pinpoint quiz. Zero dependencies." \
  --push

gh repo edit --add-topic india,history,atlas,interactive-map,svg,education,open-source,historical-maps,geojson
```

Then **Settings → Pages → Source: GitHub Actions**. The committed workflow publishes to
`https://mendax-iitm.github.io/chronicles-of-india/` on every push to `main`.

## Step 3 — Start Claude Code

```bash
cd ~/Side\ Projects/chronicles-of-india
claude
```

Paste the kickoff prompt below as the first message.

---

## The kickoff prompt (copy this whole block)

```
Read BRIEF.md, CLAUDE.md and docs/ROADMAP.md before doing anything. BRIEF.md is the
single source of truth; §6 is the feature-parity checklist and §11 is a binding
editorial policy.

Context: index.html is a working prototype whose geography is entirely hand-drawn by
eye — a 50-point coastline and ~25 blob "atoms" for kingdoms. Phase 1 replaces all of
it with real geodata. Nothing else changes in this phase.

Do Phase 1 in this order, stopping for my review at each ◆ checkpoint:

1. Set up scripts/build-geo.mjs. Download Natural Earth 10m coastline, countries,
   rivers+lake centerlines and lakes. Clip to roughly lon 58–98, lat 5–38. Simplify
   with mapshaper to the lightest vertex count that still looks right at our zoom
   range. Round coordinates to 2 decimal places. Emit data/base.json per the schema in
   docs/DATA-MODEL.md. Commit both the script and its output — a contributor must never
   need to run the build just to view the site.

   ◆ CHECKPOINT: render the new coastline and rivers in the existing page and show me a
   screenshot before going further.

2. Add relief polygons for the Himalaya, Western and Eastern Ghats, Vindhyas, Satpuras,
   Aravallis and the Thar. Physical geography is not politically contested, so
   hand-tracing these from a public-domain physiographic source is acceptable.

3. Redraw the region atoms against the real coastline, rivers and watersheds. Raise the
   count from ~25 to 40–60 for finer control — for example split DECCAN into the
   Telangana, Rayalaseema and Karnataka plateaus. Keep the existing clip-to-coastline
   trick: coastal atoms should overshoot into the sea.

   ◆ CHECKPOINT: show me the atoms rendered with labels, and the 261 BCE, 1526 CE and
   1947 CE snapshots, before I accept them.

4. Terrain hillshade from a public-domain DEM at about 1 km/px, generated by
   scripts/build-terrain.mjs, lazy-loaded so it never blocks first paint.

5. Projection decision: we currently use equirectangular with a 0.93 x-factor. A Lambert
   conformal conic at 23°N, 80°E would be more honest about India's shape. Prototype it,
   tell me what it costs in label-placement and hit-testing complexity, and recommend —
   but do not switch without my go-ahead.

Hard constraints, do not break any of these:
- Zero runtime dependencies. No CDN scripts, no framework, no build step to VIEW the site.
- Public domain or permissive licences only. Natural Earth is the default.
  Do NOT use CHGIS or any CHGIS-derived data. Do NOT trace a copyrighted atlas — you may
  consult Schwartzberg or Habib for where borders roughly were, since facts are not
  copyrightable, but their artwork must never be traced.
- Total page weight under 2 MB, 800 KB preferred, terrain excluded and lazy-loaded.
- After every change: open the page, drag the slider end to end, confirm a clean console,
  and check it at 390px and 1440px.
- Keep window.atlas stable — tests depend on it.

Work in small commits, one per checklist item. Tick items in docs/ROADMAP.md and the §6
checklist as they land. Start with step 1 and stop at the first checkpoint.
```

---

## What to expect from session 1

A `scripts/build-geo.mjs`, a real `data/base.json`, a page that looks noticeably more like
India, and a recommendation on the projection. **Not** new kingdoms, new eras or new
features — Phase 1 is deliberately only geography.

## If Claude Code drifts

The two most likely drifts, and the correction:

- **It starts adding features.** → *"Stop. We are on Phase 1 — geography only. Features
  come in Phases 3–6."*
- **It reaches for a library or a build step.** → *"Re-read BRIEF.md §5. Zero runtime
  dependencies and no build step to view the site are hard constraints."*

## Subsequent sessions

Open with: *"Read BRIEF.md and docs/ROADMAP.md. Phase N is next — start with <item>."*
One phase per session works well. Phase 3 (content depth, 18 → ~200 snapshots) is the
long one and should be split across many sessions, ideally one period per session.
